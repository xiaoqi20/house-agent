# 技术栈选型（前后端分离 · 一期）

> 版本：v1.0 ｜ 2026-09-06 ｜ 决策原则：单人可完成、依赖少、LLM 结构化输出是链路核心、每层有明确升级路径。

## 0. 仓库形态

单仓双目录（monorepo），不做两个仓库：

```
house-agent/
├── web/          # 前端 Vite + React SPA
├── server/       # 后端 FastAPI
├── doc/          # 本文档体系
├── evals/        # 20 份标注合同 + ground truth（一期评测资产）
└── 租房知识图谱-Agent-Frontend-Protype.html   # 原型（视觉基准）
```

理由：一期前后端同节奏演进，单仓一份 CI、接口改动原子提交；分仓只在发布节奏独立后才有收益。

## 0.6 环境备注（本机实测）

- 包管理器用 **pnpm**（npm 客户端直连官方源被 ECONNRESET、npmmirror 又串行过慢；pnpm 高并发+复用 store 可稳定装完）
- dev 端口固定 **5273 + strictPort**（5173 被本机 uni devserver 占用）
- `pnpm-workspace.yaml` 需 `allowBuilds.esbuild: true`，否则 vite build 被 pnpm 11 的 build-script 审批拦截

## 1. 前端 web/

| 关注点 | 选型 | 理由 |
|--------|------|------|
| 构建 | **Vite 6 + React 18 + TypeScript 5** | 前后端分离后不需要 SSR/BFF，Next.js 的重型能力冗余；SPA 更轻 |
| 样式 | Tailwind CSS + **shadcn/ui** | 原型即 Tailwind 工具类，迁移成本≈0 |
| 路由 | React Router 6 | 页面仅 2 个：对话工作台 / 合同抽屉 |
| 服务端状态 | **TanStack Query v5** | 缓存、重试、乐观更新；对话消息流不进全局 store |
| 本地状态 | Zustand | 仅抽屉开关、输入框草稿等 UI 态 |
| 实时通道 | **SSE**（fetch + ReadableStream） | Agent 流式回答 + 解析进度 checklist 步骤推送；不需要 WebSocket |
| 接口契约 | OpenAPI → **orval / openapi-typescript** 生成类型与 client | 前后端零口头对齐，后端 schema 是唯一事实源 |
| 规范 | ESLint + Prettier + Husky | 基础约束 |

> 面试追问预案"为什么不用 Next"：无 SEO/SSR 需求，FastAPI 已是后端边界，再加一层 Node 框架只会双份心智；页面按 App Router 兼容结构组织，未来要迁随时可迁。

## 2. 后端 server/

| 关注点 | 选型 | 理由 |
|--------|------|------|
| 语言/框架 | **Python 3.12 + FastAPI + Uvicorn** | async 原生、OpenAPI 免费产出、pdf 生态在 Python |
| 数据校验 | **Pydantic v2** | 请求模型与 LLM JSON Schema 输出契约同一工具链 |
| 配置 | pydantic-settings + .env | 多环境 |
| ORM/迁移 | SQLAlchemy 2.0 (async) + Alembic | 三张表：contracts / clauses / risks |
| 数据库 | **PostgreSQL 16** | JSONB 直接存 LLM 抽取结果全量；不引 Mongo |
| PDF 提取 | pdfplumber | 文字层提取，失败降级为粘贴文本 |
| LLM 接入 | **OpenAI SDK（统一 client）** | 主：**DeepSeek-V3**（temperature=0 + json_object），备：Qwen-Plus |
| Agent 框架 | **不引 LangChain/CrewAI** | 链路只有 粘贴→抽取→规则→报告 四段线性，手写可控、调试透明；框架留到二期纠纷模拟 |
| 解析任务 | FastAPI BackgroundTasks + SSE 推进度 | 60s 内的任务不建队列；超时上限 120s 即失败可重试 |
| 鉴权 | 手机号验证码 + JWT（access/refresh）+ slowapi 限流 | 一期单用户场景够用 |
| 文件存储 | 本地 `uploads/`（挂载卷） | 二期换 OSS，接口收口在 Storage 抽象后 |
| 测试 | pytest + httpx | 评测另立脚本 `server/scripts/eval_risk.py`，读 evals/，输出查准/查全 |
| 日志 | structlog（JSON） | 不引 APM |

## 3. API 契约（/api/v1）

```
POST   /auth/sms            发送验证码
POST   /auth/login           登录 → JWT
GET    /contracts            合同列表
POST   /contracts            新建（multipart 上传 或 JSON 粘贴文本）
GET    /contracts/{id}       详情（含条款）
GET    /contracts/{id}/text  原文抽屉数据（条款 + 风险高亮位）
POST   /contracts/{id}/analyze   SSE：解析进度事件 → 完成推 risks
GET    /contracts/{id}/risks     风险报告卡数据
POST   /chat                     SSE 流式问答（引用 clauses，grounding 校验）
GET    /conversations            最近对话
```

事件约定：SSE 每条带 `event: progress | token | done | error`，前端按事件类型驱动 checklist / 打字机 UI。

## 4. 环境与部署

- **开发**：Docker Compose 起 Postgres（宿主端口 5433）；`uvicorn --port 8010` + `vite dev`（:5273，proxy /api → 8010）
- **部署**：单机 Docker Compose：nginx（托管 web 静态 + 反代 /api）+ api + db；2C4G 一台跑通
- **CI**（GitHub Actions）：server lint+test / web typecheck+build；evals 手动触发、结果入库

## 5. 明确不用（防过度工程清单）

LangChain、CrewAI、Neo4j、向量数据库、Redis、Kafka、WebSocket、微服务、K8s、消息队列、GraphQL。
每一项在二期有真实需求触发条件时才引入（图谱→出现多跳查询需求时；向量库→跨合同检索时；队列→解析 >2min 或并发上来时）。
