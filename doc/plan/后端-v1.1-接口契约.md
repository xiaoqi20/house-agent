# RentGraph 后端 v1.1 接口契约（前端联调事实源）

> 版本：v1.1 ｜ 2026-09-10
> 上游：[原型完善执行文档-v1.1](../prd/原型完善执行文档-v1.0.md)（产品/验收）、[RentGraph-技术栈选型-2026](../arch/RentGraph-技术栈选型-2026.md)（技术栈）、[后端开发方案-server.md](后端开发方案-server.md)（一期合同风险雷达，本版继承其 ingest/extract/rules 资产）
> 现状：`web/` 已完成原型级前端（Zustand + 本地规则，无网络层）；`server/` 仅有一期合同风险雷达后端。

## 0. 本版范围与边界

一期产品承诺 = 三条 P0 流程 + 18 条验收清单（PRD §11）。后端必须让前端把"本地假数据/假进度"替换为真实调用，同时**不改变已验收的 UI 结构与文案口径**。

- 主场景：候选房源导入 → AI 字段提取 → 用户确认 → 偏好（硬约束/软偏好）→ 可解释推荐（三视图）
- 差异化：目标房源 ↔ 合同条款逐项核验（一致 / 冲突 / 未约定 / 无法判断）+ 建议 + 谈判话术 + 原文定位
- 辅助：上下文问答（优先引用当前房源/合同，找不到依据降级通用建议）
- 贯穿：SSE 流式 + 停止 + 重试 + 任务隔离 + 工作台临时数据（`expires_at`，不承诺长期保存）

**不做**（PRD §12 + 选型 §11）：长期房源库、平台抓取、地图路线、OCR、法律结论、账号/付费/分享、向量库、Neo4j、微服务。

## 2. 通用约定

- 前缀 `/api/v1`；所有时间 ISO8601 UTC；金额为**元（int）**；缺失字段一律 `null`，禁止 `0`/`""` 冒充已确认值。
- `workspace_id` 必填（一期临时工作台 = 数据边界）；后端按 `expires_at`（默认 72h）返回 `410 WORKSPACE_EXPIRED`。
- 错误体：`{"error": {"code": "...", "message": "...", "hint": "..."}}`；HTTP 状态：400/404/410/413/415/422/500。
- 幂等：`POST /import-batches`、`/contracts`、`/recommendations`、`/verifications` 支持 `Idempotency-Key` 头；重复键返回同一资源。
- 每个响应都带 `evidence`/`source`（PRD §3.1、§9.4：不得有无依据结论）。
- 禁止词（CI 文案检查）：`真实有效`、`已验证房源`、`仅自己可见`、`我的房源库`、`平台认证`、`最新库存`。

### 2.1 统一运行与事件（SSE）

任何长任务先建 run，再订阅事件：

```
POST /api/v1/runs/{run_id}/cancel        -> {run_id, status:"cancelled"}
GET  /api/v1/runs/{run_id}               -> RunOut
GET  /api/v1/runs/{run_id}/events        -> SSE（支持 Last-Event-ID 重连）
```

事件信封（每条 `data:` 一行 JSON，`event:` 与 `type` 同值）：

```json
{"event_id":"1","type":"progress|token|interrupt|done|error|cancelled",
 "run_id":"...","workspace_id":"...","thread_id":"...","house_id":null,"contract_id":null,
 "seq":1,"data":{...}}
```

- `progress`：`{"step":"parse|extract|verify|rank|answer","index":0,"label":"解析文档","status":"active|done","detail":"识别 5 套"}`
- `token`：`{"text":"..."}`（问答/解释流式；仅 `chat`、`recommend`、`verification`）
- `interrupt`：`{"kind":"import_confirm","batch_id":"...","draft_count":5}`（等待用户确认）
- `done`：`{"result": <对应 Out 对象>}` —— 前端**只用 done.result 落库**，避免二次请求竞态
- `error`：`{"code":"LLM_UNAVAILABLE","message":"...","hint":"..."}`
- `cancelled`：`{"reason":"user"}`

隔离规则（选型 §8）：前端只接受当前 `run_id` 事件；`cancel` 后节点边界停止；迟到结果不写入上下文。切换会话/房源/合同时前端先 `cancel`。

## 4. 端点清单

### 4.1 工作台 / 健康

```
GET  /healthz                       -> {ok, db, llm_provider, version}
POST /api/v1/workspaces             -> WorkspaceOut{id, expires_at}
GET  /api/v1/workspaces/{id}        -> WorkspaceOut{..., houses_count, contracts_count, ctx}
PUT  /api/v1/workspaces/{id}/ctx    {house_id?, contract_id?} -> WorkspaceOut
```

### 4.2 房源导入（P0-A：粘贴 / 手动 / 批量 / 文件）

```
POST /api/v1/import-batches
  body(JSON)   {workspace_id, source: paste|manual|batch|link, text, link_url?}
  body(multipart) workspace_id, source=file, file=<xlsx|xls|docx|doc|txt|csv|md>
  -> 202 {batch_id, run_id, status:"parsing"}
GET  /api/v1/import-batches/{batch_id}          -> BatchOut{drafts:[HouseDraft], count, status, error}
POST /api/v1/import-batches/{batch_id}/confirm  {houses:[HouseConfirm]} -> {houses:[House], run_id}
POST /api/v1/import-batches/{batch_id}/cancel
```

- `HouseDraft` = House 字段 + `confidence` + `evidence:{field: 原文片段}` + `missing:[字段中文名]` + `duplicate_of: house_id?`（重复提示）。
- `HouseConfirm` = 用户在字段确认面板里改过的值（租金/押金/物业费/通勤/户型必填其一可空但标记 `待确认`）。
- 3—10 套约束：`confirm` 时校验候选总数（>10 → `422 TOO_MANY_HOUSES`，<3 允许但返回 `hint`）。
- 未经确认的字段**不得**进入推荐（PRD §6.2）：只有 `confirm` 后的 `houses` 参与推荐。

### 4.3 房源（本次候选）

```
GET    /api/v1/houses?workspace_id=&status=active|dropped|all&q=&sort=
POST   /api/v1/houses                       HouseCreate（手动填写单条）
GET    /api/v1/houses/{id}                  HouseOut（含 evidence/completeness/missing/verify/todos/visits/contract）
PATCH  /api/v1/houses/{id}                  {字段子集 | notes | status | drop_reason | todos | visits}
DELETE /api/v1/houses/{id}
```

### 4.4 偏好

```
GET /api/v1/preferences?workspace_id=   -> PreferenceOut{version, budget, commute, need_bathroom, allow_shared, soft{}}
PUT /api/v1/preferences                 -> PreferenceOut（version+1；无效输入 422 INVALID_PREFERENCE）
```

### 4.5 推荐（P0-A：三视图 + 可解释）

```
POST /api/v1/recommendations  {workspace_id, view: mix|budget|commute}  -> 202 {run_id, recommendation_id}
GET  /api/v1/recommendations/{id}   -> RecommendationOut
```

`RecommendationOut`：

```json
{
  "id":"...","prefs_version":3,"created_at":"...",
  "snapshot": {"houses":[HouseOut...],"prefs":PreferenceOut},
  "views": {
    "budget":  {"order":["house_id"...],"items":{"house_id":{"rank":1,"monthly_cost":5920,"one_time_cost":11600,"hard_violations":[],"soft_hits":["南向"],"soft_miss":[],"verdict":"优先考虑"}}},
    "commute": {...}, "mix": {...}
  },
  "explanation": {
    "house_id": {"why":["..."],"tradeoffs":["..."],"risks":["..."],"todos":["..."],"next":["查看详情","上传合同"]}
  },
  "about": {"hard_rules":["..."], "soft_rules":["..."], "missing":["..."]}
}
```

- **确定性**：`hard_violations`、`monthly_cost`、`one_time_cost`、三视图排序全部由 `services/domain.py` 纯函数计算，LLM 只写 `explanation`（理由/取舍/风险/待确认/下一步），且数字必须来自计算结果（后置校验：解释里出现的金额必须能在计算结果中找到，否则剔除该条）。
- **会变**：`prefs` 变化 → `recommendation_runs` 新快照（旧报告不误导，PRD §7 快照要求）。

### 4.6 合同（原一期能力 + 房源绑定）

```
POST   /api/v1/contracts           {workspace_id, house_id?, text} | multipart file(pdf|txt|docx)
  -> 202 {contract_id, run_id}
GET    /api/v1/contracts?workspace_id=          -> [ContractOut]
GET    /api/v1/contracts/{id}                   -> ContractOut
GET    /api/v1/contracts/{id}/text              -> ContractTextView{clauses:[{clause_no,title,text,page,char_start,char_end,risk_level?}]}
DELETE /api/v1/contracts/{id}
POST   /api/v1/contracts/{id}/retry             -> 202 {run_id}
```

- `ContractOut` 与前端 `Contract` 同构：`{id, no, name, source, time, status, reason, size, bound_house_id, clauses_list:[[no,title,text]], risk_clauses:[no], negotiation, health_score}`。
- 解析失败：`pdf` 无文字层 → `422 NO_TEXT_LAYER`（前端引导粘贴）；`.doc` → `415 UNSUPPORTED_FORMAT`；`.docx/.xlsx/.txt/.md/.csv` 支持。
- 条款必须带 `page`/`char_start`/`char_end`（PRD §3.3 原文定位）。

### 4.7 房源承诺 × 合同核验（P0-B）

```
POST /api/v1/verifications  {workspace_id, house_id, contract_id} -> 202 {verification_id, run_id}
GET  /api/v1/verifications/{id} -> VerificationOut
```

```json
{ "id":"...","house_id":"...","contract_id":"...","status":"done",
  "summary": {"consistent":2,"conflict":3,"unspecified":2,"unknown":1,"high_priority":["物业费","押金/付款方式"]},
  "items": [ {"claim":"月租 5,800 元","field":"租金","anchor":"hd-rent","clause_id":4,
              "clause_text":"第五条 租金：月租金为人民币 6,000 元","page":2,"char_start":120,"char_end":150,
              "result":"冲突","advice":"...","severity":"high"} ],
  "negotiation": "房东您好，第 5 条…（逐条话术，可整段复制）" }
```

- `result ∈ 一致|冲突|未约定|无法判断`；**未匹配到条款必须是 `未约定`**，禁止推断为已承诺（PRD §3.3）。
- 每个 item 必须能回到房源字段（`field`/`anchor`）与合同原文（`clause_id`/`page`/`char_start`）。
- 数值/日期/枚举类比较走确定性规则（`services/verify_rules.py`）；语义类（维修责任、口头承诺）走 LLM 判断 + grounding 校验；两者结果合并，冲突优先展示。

### 4.8 上下文问答（P0-C）

```
POST /api/v1/conversations                        {workspace_id, title?} -> ConversationOut
GET  /api/v1/conversations?workspace_id=          -> [ConversationOut]
GET  /api/v1/conversations/{id}/messages          -> [MessageOut]
POST /api/v1/conversations/{id}/messages          {text, house_id?, contract_id?} -> 202 {run_id, message_id}
DELETE /api/v1/conversations/{id}
```

SSE `token` 流 + `done.result`：

```json
{"message_id":"...","mode":"context|house_only|general|refusal|out_of_scope",
 "html":"<p>…</p>","citations":[{"clause_id":9,"label":"第 9 条","contract_id":"...","page":3,"char_start":210,"char_end":260}],
 "followups":["..."]}
```

- 引用必须存在性校验：`[第N条]` 不在该合同条款集合中 → 剔除该引用并降级措辞（不得声称"根据你的合同"）。
- 无上下文 → `general`：先给通用原则，再问城市与阶段（PRD §5 流程 C）。
- 法规类 → 必须带 `source`（如 `flk.npc.gov.cn`）与"不构成法律结论"提示；超范围（买房/房价预测）→ `out_of_scope`。
- 移除上下文后（ctx 为空调用）回答不得再引用合同。

## 8. 与选型文档的偏差（显式记录，均为可替换实现）

| 项 | 文档 | 本版实现 | 原因与升级路径 |
|---|---|---|---|
| Postgres 18 | 生产库 | 默认 SQLite（`DATABASE_URL` 切 PG）；模型层 `JSON.with_variant(JSONB)` | 本机无 PG 且 Docker 未启动。`docker compose up -d db` + 环境变量即可切到文档口径，无需改代码 |
| Redis + ARQ Worker | 异步任务与事件流 | 进程内 `RunManager`（asyncio 任务 + 事件日志 + 取消标记 + SSE 订阅） | 一期单机演示足够；事件信封、`run_id/thread_id/workspace_id`、`Last-Event-ID` 重连、`/runs/{id}/cancel` 已按文档 §8 设计，替换成 ARQ+Redis Stream 时前端协议不变 |
