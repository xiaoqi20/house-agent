# 一期方案：合同风险雷达（唯一闭环）

> 版本：v1.0 ｜ 日期：2026-09-06 ｜ 状态：已评审（对一期范围做减法）
>
> 原则：**砍范围、做深度**。一期只做一条端到端闭环——"上传合同 → 指出风险并定位原文"。
> 其余模块（图谱可视化、时间线、纠纷模拟、房源分析、个人知识库）全部延期。

---

## 1. 一句话范围

用户粘贴或上传一份租房合同，Agent 在 60 秒内产出**可点击定位到条款原文的风险报告**，并附修改建议与谈判话术。

## 2. 闭环五步

| 步骤 | 内容 | 关键约束 |
|------|------|----------|
| ① 导入 | 粘贴文本 + PDF（pdfplumber 文字层提取） | 一期**不做 OCR**，电子合同基本都有文字层；拍照件二期 |
| ② 条款抽取 | LLM + JSON Schema 输出结构化条款 | 强制 schema 校验；条号/类型/原文/金额/日期/当事人 |
| ③ 风险扫描 | 规则库（约 40 条）+ LLM 兜底判断 | 每条风险**必须 grounding 到条款 id**，禁止凭空生成 |
| ④ 定位与建议 | 点风险 → 原文高亮 + 修改建议 + 谈判话术 | 输出的是"建议"，不是法律结论（免责） |
| ⑤ 评测 | 人工标注 20 份真实合同，算风险查准/查全率 | 这是与 demo 选手的分水岭，必须交付数字 |

## 3. 明确不做（及后手）

| 不做 | 原因 | 后手 |
|------|------|------|
| Neo4j 知识图谱 | 条款 JSON 本身就是图谱原料，一期无多跳查询需求 | schema 先行，二期加图零迁移成本 |
| OCR | 电子合同有文字层；OCR 引入噪声会污染抽取评测 | 二期支持拍照件 |
| 时间线可视化 | 时间/日期节点②已抽出，只差渲染 | 二期前端直接消费结构化数据 |
| 向量库 / RAG 问答 | 问答范围 = 单份合同条款，结构化检索更准更便宜 | 二期多文档时再引入 |
| 纠纷模拟 / 房源分析 / 个人知识库 | 依赖图谱积累，无数据则空转 | 按 PRD Phase 排期 |
| 响应式 / 计费 | 一期为桌面工作台与面试演示 | Phase 2 |

## 4. 数据模型（Postgres）

```sql
contracts(id, user_id, filename, source_type, raw_text, health_score, created_at)

clauses(id, contract_id, clause_no, clause_type,     -- 押金/违约金/租期/维修/续约/解约...
        title, raw_text, amount, date_from, date_to, party_liable)

risks(id, contract_id, clause_id, level,             -- high / medium
      rule_id, title, reason, suggestion, negotiation_script)
```

条款抽取 JSON Schema（LLM 输出契约）：

```json
{
  "clauses": [{
    "clause_no": 8,
    "clause_type": "违约金",
    "title": "违约责任",
    "raw_text": "任何一方违约的……月租金的三倍……",
    "amount": null, "months": 3,
    "party_liable": "双方"
  }]
}
```

## 5. 风险规则库（样例，一期先写 10 条）

| # | 规则 | 触发条件 | 等级 | 建议方向 |
|---|------|----------|------|----------|
| 1 | 违约金过高 | 违约金 > 1 个月租金 | 高 | 改为 1 个月 |
| 2 | 押金无退还时限 | 押金条款缺"X 日内退还" | 高 | 补 15 日退还 |
| 3 | 扣款标准模糊 | "损坏"无定价/折旧依据 | 高 | 按市场价折旧+凭证 |
| 4 | 自动续约陷阱 | 未通知视为续约且涨租 | 中 | 删除，另行协商 |
| 5 | 维修责任全倒向租客 | 自然损耗也由乙方承担 | 中 | 区分使用不当/自然损耗 |
| 6 | 提前解约单方权 | 仅房东可提前解约 | 高 | 对等条款 |
| 7 | 转租一刀切禁止 | 任何转租均违约 | 低 | 允许经书面同意转租 |
| 8 | 租金支付周期 > 3 个月 | 押二付六等 | 中 | 押一付三 |
| 9 | 无退租交房流程 | 缺交接单约定 | 中 | 补《房屋交接单》 |
| 10 | 隐性费用未列明 | 物业/供暖/网费无归属 | 低 | 列明费用清单 |

## 6. 评测方案

- 样本：20 份真实北京/杭州租房合同（自如、中介、个人房东混合）
- Ground truth：人工标注风险条款清单
- 指标目标：规则命中 recall ≥ 90%，端到端（抽取+判定）precision ≥ 70%，recall ≥ 80%
- 每次 prompt/规则变更跑一遍回归，报告进 git

## 7. 里程碑（3 周）

| 周 | 交付 |
|----|------|
| W1 | 导入 + 抽取：粘贴/PDF → clauses 表，schema 校验通过率 ≥ 95% |
| W2 | 规则扫描 + 定位 API：risks 表、原文高亮接口、话术生成 |
| W3 | 前后端联调（原型页接真实 API）+ 评测报告 + 演示脚本 |

## 8. 演示验收脚本（对应原型交互）

1. 首页居中对话框粘贴"审查刚上传的《房屋租赁合同》"
2. 进度 checklist：解析文档 → 抽取条款 → 匹配规则库
3. 风险雷达卡片：高 2 / 中 1，健康度分数，每条带条款溯源
4. 点击风险 → 右侧合同原文抽屉滑出，黄色高亮对应条款
5. 一键复制谈判话术 / 导出报告
6. 追问"违约金怎么谈" → Agent 引用第 8 条原文回答

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| PDF 版式乱码 | 提取失败即引导用户粘贴文本，不阻塞 |
| LLM 幻觉出不存在的条款 | 输出只允许引用 clauses 表已存在的 id |
| 健康度打分被当成法律结论 | 全链路免责文案 + 建议均附规则依据 |
