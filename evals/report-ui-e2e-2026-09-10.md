# RentGraph 前端端到端测试报告（Playwright CLI 有头模式）

- 日期：2026-09-10
- 环境：`web/`（Vite dev @5174，`VITE_API_MODE=api`）+ `server/`（uvicorn @8010，`LLM_PROVIDER=mock`，SQLite）
- 工具：`playwright-cli 0.1.19`，`--headed` 有头模式，真实浏览器交互
- 结论：**核心链路（导入 → 确认 → 推荐 → 核验 → 问答）可用；发现 2 个 P0/P1 级缺陷（推荐崩溃、重复房源未跳过）与 5 个 P2/P3 缺陷**

## 2. 缺陷清单

### 缺陷 1【P0】推荐流程崩溃 IndexError（前端显示为"服务不可用"）
- 现象：候选含两套"同名同租金"完全相同的房源时，点"开始筛选"必现"处理失败 / 服务暂时不可用"，错误码 `SERVICE_UNAVAILABLE`。
- 证据：SSE 事件 `{"code":"INTERNAL_ERROR","message":"服务异常：IndexError"}`；本地复现堆栈：
  `domain.py:414 _tie_break_note → labels[index] IndexError: tuple index out of range`。
- 根因：`server/src/rentgraph/services/domain.py`
  - `_view_key("budget")`（391-395 行）返回 **5 元组**（首项为"租金缺失"标记）；
  - `_SORT_LABEL["budget"]`（341-345 行）只有 **4 个标签**；
  - 当相邻可比房源前 4 个排序键完全相同时，`_tie_break_note` 取 `labels[4]` 越界。
- 触发条件：budget 视图下相邻两行 `(租金缺失标记, 月度成本, 通勤, -完整度)` 全等 —— 典型场景即重复导入的同名同价房源。
- 修复建议：`_SORT_LABEL["budget"]` 补"租金缺失"标签（与 `_view_key` 对齐）；或 `_tie_break_note` 对越界索引兜底。另建议前端对 5xx 内部错误展示"服务内部错误"而非"请确认后端已运行"的误导文案（`web/src/controller.ts:203-213`）。

### 缺陷 2【P1】"疑似重复，确认时将跳过"未兑现，重复房源被真实加入
- 现象：批量导入与已有房源同名同租金的条目，确认面板提示"疑似与「…」重复，确认时将跳过"；确认后重复项**仍被加入**（实测 H1/H2 同名同价并存），且底部"确认后新增 X 套"计数未扣除重复项。
- 根因：跳过逻辑只存在于 demo 模式（`web/src/controller.ts:1096-1113`），api 模式走后端 `confirm_import`
  （`server/src/rentgraph/services/flows/import_flow.py:128-157`），后端**只追加 `duplicate_notes` 提示、不跳过**（`db.add(house)` 无条件执行）。
- 影响：连锁触发缺陷 1（推荐崩溃）；数量上限被重复项挤占；"对比 3—10 套"语义被污染。
- 修复建议：统一口径 —— 后端 confirm 时按 `_dup_key` 跳过或前端文案改为"将标记疑似重复"；`pendingCount` 需按实际新增数展示。

### 缺陷 3【P1】删除房源后再导入，房源编号重复
- 现象：删除 H1/H2 后重新导入，API 返回中出现 **两个 H3、两个 H4**（不同房源、同名不同物）。
- 根因：`import_flow.py:125` `seq = active_count`（而非现有最大编号），删除产生空洞后新编号回退撞号。
- 影响：推荐/核验/提示均以 `H编号` 指代房源（如"排序第 1 名：H4"），撞号会导致指向混乱。
- 修复建议：按 `max(no)` 或工作台级单调自增分配编号。

### 缺陷 4【P2】"定位合同原文"未滚动定位、未高亮目标条款
- 现象：核验冲突项 →"定位合同原文"、问答引用 chip 点击，均只打开合同抽屉并停在条款列表顶部，不滚动到目标条款，也无界面承诺的"黄色高亮"（DOM 检查无任何 amber/yellow 高亮元素）。
- 证据：两次操作后截图 + `document.querySelector('[role=dialog]')` 检查。
- 修复建议：打开抽屉后 `scrollIntoView` 目标条款并加高亮类；或修正界面说明文案。

### 缺陷 5【P2】api 模式上传 Excel 误报"原型未接入真实文件解析"
- 现象：真实后端解析 houses.xlsx 成功（识别 4 套）后，确认面板仍显示"原型演示解析提示：当前前端原型未接入真实文件解析服务"。
- 根因：`web/src/components/ImportModal.tsx:231-233` `isDemoFile` 以来源字符串包含 `file-xls/file-doc` 判定，与真实来源（`file-xlsx` 等）命中。
- 修复建议：`isDemoFile` 仅在 demo 模式或明确演示来源时展示。

### 缺陷 6【P2】推荐失败后顶部状态卡死"服务不可用"，需刷新才恢复
- 现象：一次 INTERNAL_ERROR（5xx）后 header 永久显示"服务不可用"；随后推荐成功、导入成功均不恢复，刷新页面才回到"Agent 在线"。
- 根因：`controller.ts:217` `set({ serviceOnline: false })` 后缺少成功路径复位。
- 修复建议：任何成功响应/健康检查通过时复位 `serviceOnline`。

### 缺陷 7【P2】切换推荐视图后"排序第 N 名"文案与当前排序不符
- 现象：切到"按通勤"视图，H3（25 分钟）升至第 1，但卡片仍写"排序第 3 名"（沿用综合匹配时的解释）。
- 根因：explanation 按 mix 生成一次，前端切换 view 只换排序不解绑解释。
- 修复建议：解释文案按视图生成，或标注"以下说明基于综合匹配排序"。

### 缺陷 8【P3】"返回重新导入"未回到原输入 tab
- 现象：粘贴单条失败后点"返回重新导入"，弹窗回到"批量粘贴"tab（且保留上次演示文本），用户失去原输入。
- 修复建议：按失败来源 tab 回退（`importFail.backTab` 已具备该字段，检查赋值）。

## 3. 观察项（非缺陷，建议记录口径）

1. 单条导入曾出现 1 次"事件流中断"（后端 `done` 事件已成功发出，浏览器端未收到）；未能稳定复现，建议后续压测 SSE 分帧/重连。
2. 未匹配意图的问答（如"附近有健身房吗"）回答为"当前上下文"摘要 + 引导问题，且附带第一条合同条款引用（mock 兜底设计，`server/.../llm/mock.py:588-606`）；引用关联性弱，建议无依据时不附引用。
3. "点我用示例"使用内置示例合同（望京 68.5㎡）对 H4（回龙观 55㎡）核验出 5 处"冲突"——数据本就无关，属演示口径，建议演示脚本中说明。
4. 移除房源实际为"删除"（无已放弃状态流转）；筛选下拉中"已放弃"选项暂无对应状态。
5. favicon.ico 404。

## 4. 修复优先级建议

| 优先级 | 项 | 理由 |
|---|---|---|
| P0 | 缺陷 1 | 推荐主链路必现崩溃，且错误文案误导 |
| P1 | 缺陷 2、3 | 数据正确性（重复入库、编号冲突），连锁影响推荐与核验指代 |
| P2 | 缺陷 4、5、6、7 | 承诺未兑现/文案错误/状态不自愈，影响信任与可解释性 |
| P3 | 缺陷 8、观察项 | 体验细节 |

## 5. 复现要点（供回归）

- 崩溃复现：连续两次导入完全相同的"名称+租金"房源各 ≥1 套（或 `houses.ts` 同样的重复数据），点"开始筛选"即触发。
- 重复未跳过：任意一次"批量粘贴中含与已有候选同名同租金条目"→ 确认 → 侧边栏计数可见 +1。
- 编号冲突：先删除任意房源，再导入新批次，`GET /api/v1/houses?workspace_id=…&status=active` 可见重复 `no`。
